Part one

What we know about the model

Everything below is measured, not recalled. Two corpora sit on disk: EA's GPL v3 engine source, whose FieldParse tables define every legal field of every content type, and the retail content itself. A deterministic extractor (tools/zhasset) turns both into queryable JSON, so any figure here can be regenerated rather than trusted.

110 : 1
Art-to-content bytes. Roughly 1.94 GB of binary against ~18 MB of text.
35 archives · 26,264 files · 9,000 models · 7,891 textures

That ratio is the single most important fact about the subject, and it is why an art-free platform is not a compromise. Inside Zero Hour an agent can author roughly the 58,000 lines of text a total conversion needs — 5–10% of the job. The remaining 90–95% is a binary asset pipeline it cannot touch. On this platform that 5–10% is the entire product.

The generals are forks, not diffs

Zero Hour's headline feature is twelve generals. In the shipping content they are implemented by copy-paste: every one of the 532 general-prefixed objects is a clone of an existing base object, and none is authored from scratch. The engine has an inheritance keyword — ChildObject — used exactly zero times.

96.4%
of general content is byte-identical to its parent. 202,322 lines shipped to express about 9,297 lines of real intent.
433 mechanically diffed pairs · ~111 scalar balance overrides in total

The diagnosis matters more than the number. Field-level overrides alone would not have fixed it: a general is six pointer swaps in a 34-line template, and those swaps cascade — new command centre forces new dozer forces new buildings forces new units. Without reference scoping, expressing a diff still means restating the transitive closure.

The behaviour system collapses

Extensibility in ZH is ~217 compiled C++ module classes named from data. That is also its wall: every new behaviour is a recompile, so every mod needing one is dead on arrival. The distribution says the wall buys very little.

  • 7 modules cover 50% of all usage; 27 cover 80%; the 60 rarest are 1.07%.
  • 86.7% of non-draw instances are pure data, averaging 3.89 parameter lines.
  • All eleven death-family classes share one filter schema, differing only by a single typed effect — 5,083 instances, one rule shape.

Combat is one table

All rock-paper-scissors is a 57 × 38 damage-type × armor-class multiplicative lookup. Units carry no "anti-tank" stat — only a damage-type label whose meaning lives entirely in that table. 47.5% of hand-authored cells are 0%: half the authoring effort is spent saying "this does nothing to me". Bonuses compose additively in excess of 1, so veteran 1.10 + upgrade 1.25 gives 1.35, not 1.375 — deliberately anti-combinatorial.

Terrain is gameplay-dead

The most counter-intuitive finding, and it reordered our roadmap. Terrain.ini has 291 blocks and one gameplay call site — a flag no shipping terrain sets. Elevation confers no damage, no range, no cover. "Chokepoint" does not exist in the engine. The only terrain-shaped combat modifier in the entire game is GARRISONED, and it needs no geometry at all.

Part two

Where the platform stands

Their schema is the target model — we adapt to it rather than grow a parallel vocabulary, so content and knowledge transfer both directions. Coverage below measures what we simulate. Now that the output runs on their engine, a second axis matters just as much: what we can emit. A unit needs a command button, a numbered command-set slot and string labels or it is invisible in-game however correct its stats are — so we must emit fields we will never simulate. Conflating the two would ship packs that measure beautifully and never appear.

What has landed

Layered content packs + rts diff

done

A mod is a patch, not a fork. Vocabularies union with order preserved; the damage matrix merges per cell. rts diff names what changed by category and reports duplication ratio — the thing ZH's whole-corpus checksum cannot do.

30-line mod · 4 changes named · base pack provably uncontaminated

Schema hygiene

done

A defaults block so new fields stop being breaking changes, durations quantised to whole ticks with ceil() at load, and units-per-purchase so cost-per-unit figures are honest.

hash-neutral

Structures

done

A structure is a unit with speed 0, KindOf role flags and BuildCompletion — their model exactly, not a new content type. Prerequisites became objects, so razing a factory revokes buildability. That is what makes a building a target rather than scenery.

no factory → defeated 3/3 · factory present → builds and wins 3/3

Weapon vocabulary

done

Splash as their two-band step function with no falloff, clips, and minimum range. The artillery unit that emerged behaves like artillery by mechanics rather than by design: beats a tank at range, loses to infantry that closes inside its minimum.

identical paper DPS, splash on/off: 9.4s → 7.2s to resolve

Flags and conditional variants

done

Their real upgrade mechanism: an upgrade carries no effect data, it sets a condition bit and a condition-keyed loadout is selected. A flag set rather than their single bit removes the 268 exclusion lines that bit forced on their content.

ablation: 9/12 wins with the variant, 0/12 without

Event rules {on, when, do}

done

The replacement for 217 compiled module classes. Closed event enum, closed filter, closed effect enum with open parameters — not a scripting language. Cascades bounded at four generations and clamped, never thrown.

spawn 23/40 vs 3/40 ablated · salvage 15,506 vs 14,250 net worth

Startable factions + rts skirmish

done

A faction that declares its starting building, units and money is playable, not just a roster. Both sides start from their own definitions rather than from a build order someone typed.

working power grid beats +2,000 cash, 12/12

rts compile --target zh

done

Packs now leave the harness and run on the retail engine. Output is additive: for each content type ZH loads X.ini and then scans the directory X/, so writing Data/INI/Weapon/<pack>.ini appends to retail's 363 weapons instead of replacing the file and deleting them all. Death rules compile to real modules; conditional variants compile to an Upgrade block, a condition-keyed loadout and the parameterless module that flips the bit.

9 content types emitted · 42/42 subsystems · 0 parse errors · main loop entered

Divergence as a first-class report

done

The dangerous failure is not a pack that will not load — it is one that loads, plays, and behaves differently from the numbers it was tuned against. rts lint --target zh separates three questions that fail differently: their compile-time caps, whether a duration survives ticks → ms → their ceil() back to the same tick, and which of our mechanics has no faithful carrier. Each unmappable feature is named individually, so the list shrinks as the compiler grows instead of staying a warning nobody reads.

4 invented enum values caught only here · every emitted literal now copied from a block that demonstrably loads

Decisions taken, closed

  • Stacking: additive-in-excess added as a third op alongside Add and Mul; mixing them on one stat lints.
  • Rule bounds: spawn cascades cap at 4 generations and clamp — a content bug degrades a battle, it never crashes a sweep.
  • Retail as a reference pack: never The GPL covers the engine source only; the data stays EA's. Extractors ship, extracts do not.
  • Tick order: a flag change re-selects a loadout, which changes stats — so loadout re-resolve is its own pinned phase between production and cooldowns.
  • Terrain: stays late and stays a passability grid. Their own data says a tileset is worth zero simulation.
  • Mistranslation: refused a death rule that pays its owner has no ZH carrier — the nearest module drops a crate the killer collects. Emitting it would look right and reverse who benefits, so it is reported as dropped instead. The same rule holds for spread, which we model as a damage multiplier and they model geometrically.

Part three

Corrections

Kept deliberately, because several findings only exist because something was wrong first, and because a status page that records only successes is not worth reading.

Prototype identity was ordinal — a live bug, not a hypothetical

The state hash folded a dense table index, so adding an unrelated unit silently rewrote old replays. It had already happened: technical vs ranger had moved from c773f31f6888b7c8 to 2cdfb299cdae6006. The pinned hashes missed it because a final-state hash only observes units alive at the end, and the renumbered units were on the losing side. Identity is now name-derived, and the guard is generative rather than a recorded constant.

The asset inventory was half the art

The ZH archives are a delta over base Generals in a second layer. Counting only the top level undercounted models 4,429 → 9,000 and the whole set to roughly half its real size.

The coverage metric flattered itself

The sim/art classifier matched substrings, and "St-art-ing" contains "art" — so StartingBuilding, StartMoney and ten more of the most load-bearing faction fields were classified as art and dropped from the denominator. A smaller denominator is a higher percentage, so the bug inflated the only number we steer by. Fixed with word-splitting; coverage fell before it rose.

Three build-order tests that silently built nothing

Each named a unit whose prerequisite it never satisfied. A stalled queue was invisible — net worth counts money and army together, so it stays flat whether you spend or not, and the run reads as a dull draw. Cost three debugging rounds. The harness now names the reason, which caught the very next one on its first run.
